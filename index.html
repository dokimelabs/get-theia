Install

Linux / macOS

curl -fsSL https://dokimelabs.github.io/get-theia/install.sh | sh

The installer detects your OS and architecture, asks for the GitHub PAT your organization issued for release access (or reads $THEIA_PAT), verifies checksums, verifies the binary runs, and installs theia to ~/.local/bin. Re-running it replaces an existing install wholesale — it is also the recovery lever.

To pin an exact release instead of the latest:

curl -fsSL https://dokimelabs.github.io/get-theia/install.sh | THEIA_VERSION=0.2.201 sh

Windows

One command in PowerShell — no administrator rights. It offers GitHub sign-in (recommended; your account holds the release invite) with a pasted token as the fallback, verifies the archive and every payload file by sha256, run-checks the binary before it takes over, installs into %LOCALAPPDATA%\dokimelabs\theia\app, and adds it to your user PATH:

powershell -ExecutionPolicy Bypass -c "irm https://dokimelabs.github.io/get-theia/install.ps1 | iex"

Pin an exact version (also the recovery lever — reinstalling any version over an existing install is supported):

$env:THEIA_VERSION = "0.2.341"
powershell -ExecutionPolicy Bypass -c "irm https://dokimelabs.github.io/get-theia/install.ps1 | iex"

Unattended installs set $env:THEIA_PAT instead of signing in. Re-running the installer is safe — it reinstalls over the top and leaves your config alone. Afterwards open a new terminal, where theia is on the path. (The offline installer kit inside the release archive — install.ps1 beside theia-win-x64\ — remains for air-gapped installs.)

Releases and access

Release artifacts live in dokimelabs/theia-releases, a private repository — distribution is the access gate. Downloads (and the installer) authenticate with a fine-grained GitHub token that dokimelabs issues per customer; ask your dokimelabs contact for a release token if you don't have one. The token can download releases and nothing else.
